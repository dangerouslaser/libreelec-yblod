## What this proves—and what it does not

This verifies the adapter's metadata copying, component/guide pairing,
contiguous chunk ordering, full sample counts and finalization against an
existing native baseline. Both paths use the same integer C arithmetic core:
this result is an integration regression check, not an independent proof of
that core's mathematics. Synthetic host tests also compare against the separate
Python reference.

The input is already prepared whole-code planar data. This run does not test
decoding, hardware scaling, Y416 texture sampling, fractional or overshooting
EL policy, colour conversion, HDMI packing, real-time performance or licensed
Dolby correctness. In particular, it does not resolve the
[overshoot interface question](EL_OVERSHOOT_CONTRACT.md).

The existing saved extraction/RPU association was revalidated. That checks
hashes, normalized instructions and frame identity; it does not freshly parse
the RPU CRC, re-decode the film or rehash the original film file. It is not
authentication against an adversary controlling a self-consistent bundle.

## Execution and privacy contract

`native_integration_frame.py` reads bounded little-endian byte buffers and makes
one `yb_integration_integer` call per component chunk, with at most 65,536
samples. Pixel arithmetic stays in C. The harness compares generated bytes
directly with each saved stage and computes matching hashes; it does not write
another full set of image planes.

All seven consumed prepared files and all 12 baseline stages are fully hashed
before processing and rechecked afterward. Processing reads also check exact
size, EOF, file identity and content hash. The native baseline's saved build
provenance is required by the command-line interface. Library, build-record,
header and helper-source pins are checked, including ABI version/structure
sizes before use. These checks detect ordinary mutation, not a hostile-loader
or immutable-snapshot guarantee.

Success additionally requires arithmetic-frame completion with all three exact
counts, zero raw-diagnostic queries, unchanged association and successful
memory guards. A partial computation or late failure cannot publish a complete
summary. Disabled-EL tests explicitly omit unused EL files; they do not claim
to have consumed seven files.

Private outputs use a fresh mode-0700 directory. Only `public-summary.json`
should be published: its allowlist contains fixed role names, hashes, counts,
status and resource facts—not RPU curves, film pixels, source paths, movie
titles or raw exception messages. The API-only host-test memory bypass is
reported as `bypassed-host-test`, never as an enforced pass.

## Reproduction

From the repository root, using existing prepared and verified private bundles:

```sh
systemd-run --user --scope -p MemoryMax=512M -p MemorySwapMax=0 \
  python3 tools/yblod/reference/native_integration_frame.py build \
  target/native-integration-frame-build-FRESH

systemd-run --user --scope -p MemoryMax=512M -p MemorySwapMax=0 \
  python3 tools/yblod/reference/native_integration_frame.py run \
  target/native-integration-frame-build-FRESH/libnative_integration.so \
  target/reference-frame-2296-prepared-linear/frame.json \
  target/reference-frame-2296-independent-native-20261005a \
  target/reference-frame-2296-v7 \
  target/native-integration-frame-check-FRESH

python3 -m unittest discover -s tools/yblod/reference \
  -p 'test_native_integration_frame.py' -v
```

Use genuinely fresh output names; existing files are never overwritten. The
14 host tests passed locally. They cover polynomial/MMR and disabled routes,
different chunk sizes, exact C-dispatch counts, ABI rejection, stale metadata,
short/trailing/corrupt data, bounded reads, late source/output/resource failures,
privacy rules, source-inventory imports and no-overwrite behavior. The host
fixtures are synthetic; the measured full-frame result above is separate.

The final Ollie checkpoint also passed all **804 reference tests without skips**
(27.515 seconds) and all eight accuracy tests (0.105 seconds). The reference
suite used the existing compiled VAAPI probe for its host validation guards;
this did not launch another hardware or frame-processing cohort.
