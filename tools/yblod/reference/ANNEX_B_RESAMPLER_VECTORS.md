# Exact informative Annex B resampler answers

This is an arithmetic check, not a selected production scaling policy. The primary source is [ETSI GS CCM 001 V1.1.1](https://www.etsi.org/deliver/etsi_gs/CCM/001_099/001/01.01.01_60/gs_ccm001v010101p.pdf), clause 4 note 1 and informative Annex B, printed page 37. Resampling precedes the composer and is not normative. The example cannot establish a licensed Dolby player's filter or Dolby conformance.

## Explicit contract

Use Annex B.3's enhancement-layer example: vertical first, horizontal second; repeat the nearest boundary sample for every out-of-plane tap. Each pass adds its own half-divisor bias, divides with mathematical floor, and clips to 0..65535. Negative signed division must not truncate toward zero. No physical chroma phase adapter or inferred input/output registration is applied here.

The input is one component plane of width 2, height 2; output width 4, height 4. These dimensions are component-plane dimensions, not a complete 4:2:0 picture. Test the same plane separately as Y, Cb and Cr. Small edge-heavy dimensions deliberately exercise boundary repetition; they are not a hardware allocation recommendation.

For vertical Y, even rows use offsets −2..+1 with coefficients −3,29,111,−9; odd rows use offsets −1..+2 with −9,111,29,−3. Divisor 128, bias 64. Vertical Cb/Cr use offsets −1,0 and coefficients 64,192 for even rows; offsets 0,1 and 192,64 for odd rows. Divisor 256, bias 128. Horizontal even columns copy the vertical result; odd columns use offsets −3..+4 with 22,94,−524,2456,2456,−524,94,22. Divisor 4096, bias 2048.

## Hand-derived fixture

Input:

```text
0 1
2 8
```

Rounded/clipped vertical intermediates and final answers are literal test constants:

```text
Y vertical       Y final
0 1              0 1 1 1
0 2              0 1 2 2
2 7              2 5 7 7
2 8              2 5 8 9

Cb/Cr vertical   Cb/Cr final
0 1              0 1 1 1
1 3              1 2 3 3
2 6              2 4 6 6
2 8              2 5 8 9
```

Two discriminators make this more than a generic affine-ramp test:

- At final Y row 0, column 1, the unrounded vertical values are −18/128 and 65/128. Deferring rounding until after the horizontal pass gives their midpoint 47/256, which rounds to 0. Required per-pass rounding produces vertical values 0 and 1, then a midpoint of 1/2, which rounds to **1**.
- At final row 3, column 3, boundary repetition produces horizontal value `(−408×2 + 4504×8)/4096 = 2201/256`, which rounds to **9**. Repeated-edge bilinear interpolation would give 8. This overshoot is not clipped to the input's observed maximum.

The same tap check with native10 input rows `[0,1023]`, `[1023,0]` gives first vertical Y row `[0,1095]`. Annex B's stated 16-bit clipping is not a native10 clamp. With storage-range diagnostic rows `[0,65535]`, `[65535,0]`, the vertical Y rows are `[0,65535]`, `[13312,52223]`, `[52223,13312]`, `[65535,0]`. This second diagnostic is not a claim that native10 media contains 65535 codes.

## Test scope

Run `python3 -m unittest test_annex_b_resampler_vectors -v`. Four tests compare a separately written integer-tap test evaluator and the existing Hermite/Fraction `scaling_oracle.expand` against the literal answers, and check rounding, edge ringing and clipping. Expected values are not generated by either implementation. No compiled C implementation or GPU backend is tested by this checkpoint; a future C Annex B backend should consume these same literals. A custom bilinear experiment must remain separately named and must not inherit these Annex B claims.
