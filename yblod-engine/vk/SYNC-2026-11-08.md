# dv-engine-vk: HDR10 output (from big-fella, 2026-11-08)

big-fella's `feature/dv-hdr10-tonemap` (dv-engine-vk 0.1.0-20, not merged there yet) on top of
0.1.0-19, which this copy already had. It was applied as a diff of `dv-engine-vk/` (packaging
left out). Two hunks were placed by hand because the code around them differs here:
- `src/engine.rs`, the damage key: the HDR10 map's key is hashed, and HDR10 pictures have no
  metadata packet rows;
- `tools/dvvk-bench.c`, `--output`: next to this copy's `flip`.

The LibreELEC-only additions (`DVVK_OVERLAY_FLIP_Y`, `DVVK_SURFACE_CHECK`) are untouched.

## What it adds

HDR10 output, as optional symbols with no ABI or soname change: `dvvk_set_output_mode`
(`DVVK_OUTPUT_DV`, `DVVK_OUTPUT_HDR10`) and `dvvk_output_signal`. The engine converts
Dolby Vision to BT.2020 PQ HDR10, the Master Reference conversion. That is a 65³ LUT of output
codes; cells whose LUT error is over half a code are computed exactly by a fix-up pass. Every
pixel is within one 12-bit code of the CPU double-precision map of the Master Reference frame.

The picture keeps the tunnel's byte layout (12-bit YCbCr 4:2:2 in XRGB8888, limited range, no
metadata in it). The link signals it with `DVBRIDGE_TUNNEL_FORMAT` hdr10 (linux-9928) and the
HDR_OUTPUT_METADATA from `dvvk_output_signal`. New sources:
- `include/dvvk_map.h`, `yblod/dv_map.c`: the CPU half, which plans the map per film and scene;
- `yblod/placebo`: CB1's libplacebo e2972fdd colour, tone and gamut mapping, all symbols hidden;
- `src/map.rs`, `shaders/map_bake.comp`, `shaders/map_fixup.comp`, `shaders/common/dv_map.glsl`;
- `tools/dvvk-map-test.c`, `tools/dvvk-hdr10-compare.c`.

The design and measurements are in big-fella's `docs/hdr10-output.md`.

## Checked on Ollie (UHD 770)

- `golden.sh check` with 1917 FEL, Gemini Man MEL and 28 Years Later P8.1: identical, 90
  hashes, and the 18 FLIP_Y twins too. Dolby Vision output is unchanged.
- `cargo test --lib`: 34 passed.
- `dvvk-bench --output hdr10` on the same three clips, frames 0 and 3: byte-identical to
  big-fella's build.

## Kodi and kernel

- linux-9928 (`projects/Generic/patches/linux`) was regenerated against this tree, which has
  no linux-9926. It applies cleanly after linux-9927.
- Kodi is not switched over yet. Kodi yblod-29 (Output mode **HDR10** through the tunnel:
  the Vulkan engine's HDR10, DVBRIDGE_TUNNEL_FORMAT hdr10 and the engine's HDR metadata) is
  on branch `feature/dv-hdr10-output`. It has only been compile-checked, so it was left out
  of 0.3.4. In 0.3.4 nothing calls the new engine symbols and nothing sets the property, so
  Output mode HDR10 is still the GL conversion.
