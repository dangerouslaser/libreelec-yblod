YBLOD 0.2.5 validation

Build source: 8251ff75a178839fdf97ee2bab5e0fc6d95c1dac (PRs #9, #10, #11 on top of 0.2.4
and the repository restructure, PR #7)
LibreELEC upstream base, FFmpeg, libplacebo, kernel, native engine, engine defaults and
shaders are unchanged from 0.2.4. Kodi gains patches 21 and 22; the LG edition updates
Estuary LG to 4.1.0+lg.10.

Changes since 0.2.4
- Kodi patch 22 (native PGS subtitles): with native GUI coverage, PGS (PQ bitmap)
  subtitles are drawn into the GUI layer with their palette converted to sRGB instead of
  the late PQ back-buffer pass, which the native route refused frame by frame
  ("rejects late PQ bitmap subtitles"): playback froze for each subtitle line and the
  subtitle was not shown.
- Kodi patch 21 (Dolby Vision engine settings): Settings > Player > Dolby Vision gains
  Engine and Diagnostics groups (Expert level) mapped to the engine's environment
  switches, applied at window-system start and on change; settings take precedence over
  native-dv.env. Hidden setting yblod.build lets skins detect YBLOD.
- LG edition: skin.estuary.lg 4.1.0+lg.10 (on YBLOD the OSD process info button opens
  Kodi's player process info with the Dolby Vision panel).

Byte-exact check (N150, installed yblod-0.2.5-lg, Verify output setting on; 1917, No
Country for Old Men, Deadpool, Gemini Man, Sol Levante P8.4, each with playback controls,
Home over video, navigation, return and stop, then 1917 with English SDH PGS subtitles
for 40 s)
- Active-row reconstruction: 500 frames, 0 byte differences.
- Inline overlay pack: 573 overlay frames, including PGS subtitle frames, 0 byte
  differences over the full 3840x2160 scanout.
- Table caches rebuilt on every hit: 0 mismatches.
- No Kodi log errors, no PGS refusals, native route active throughout.

Subtitles (N150, 1917 English SDH PGS, 60 s): 23.97 fps output, 0 missed vblanks,
0 drops/skips. Same test on 0.2.4: 21.25 fps, 164 missed vblanks, freezes of 24-71
vblanks.

Settings (N150, test build with patch 21 before release): settings listed with the
expected defaults; toggling over JSON-RPC between videos switched the overlay colour pass,
verification and the native engine on the next video without restarting Kodi. On the
release image the settings apply at start and yblod.build reads true.

LG skin (N150, yblod-0.2.5-lg): Kodi uses the system Estuary LG 4.1.0+lg.10; the OSD
process info button opens player process info with the Dolby Vision panel visible
(Dolby Vision (TV-Led), profile 7, FEL Yes); no skin load errors.

Performance (N150, 30 s per cell, engine GPU ms per source frame): unchanged from 0.2.4
within run-to-run variation: 1917 19.7 / 22.8 (controls closed / open), Sol Levante P8.4
19.7 / 23.9, Gemini Man 6.7 ms with controls closed (0 missed vblanks); Gemini Man with
controls open still drops frames on the N150 (42 fps output).

Petunia VM (Tiger Lake, yblod-0.2.5-lg, no display connected, compatibility route):
boots, Kodi starts, three titles play with controls, Home, navigation and stop, zero log
errors.

Ollie Kodi container: switched to kodi-dv:yblod-0.2.5-lg, Kodi starts, no restarts.

Limitations
The standard 0.2.5 image was not separately installed; its Kodi, engine, shaders and
kernel match the tested LG image. No visual TV confirmation is part of this report; the
subtitle check proves the frames are presented and composited exactly, not how a viewer
sees them. Each subtitle line still toggles the overlay state sent to the TV (L5 and the
metadata refresh flag); no frame drops were measured from it on the N150.
