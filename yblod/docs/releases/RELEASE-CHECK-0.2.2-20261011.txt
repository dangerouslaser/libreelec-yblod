YBLOD 0.2.2 validation

Build source: 0e61204c9a3146983a216afef761e81b88f2713b
LibreELEC upstream base is unchanged from 0.2.1. Both editions are built from this
source; the LG edition with YBLOD_EDITION=lg.

Changes since 0.2.1
- Engine: paired dual-channel MMR work items; fused BL chroma phase, guide and
  paired luma reconstruction (DV_LUMA_GUIDE_FUSED=1).
- Engine and Kodi: per-frame timing logs off by default (DV_ENGINE_FRAME_TRACE=0,
  DV_PRIVATE_FRAME_TIMING=0).
- Kodi patch 16: dvbridge.chromaupscaler (Gaussian default, Lanczos) for the
  compatibility renderer.
- Kodi patch 17: the compatibility renderer accepts the ordinary GUI (no coverage-alpha
  GUI unless the native route is expected) and completes the presentation drain.
- Kodi patch 18: Settings > Player > Dolby Vision category; setting IDs unchanged.
- LG edition: skin.estuary.lg 4.1.0+lg.7, service.webostv 0.5.3 and
  repository.dangerouslaser 1.0.1 as optional system add-ons; Estuary LG is the skin
  of a fresh installation only.

Reconstruction accuracy (N150, P7 FEL fixture, real playback frames)
Engine verification against the unfused reference kernels, first three frames:
base planes 12441600 bytes, luma 16588800 bytes, each MMR chroma channel 4147200
bytes: zero byte differences in all 12 comparisons, on the installed image.
Standalone kernel tests: byte-identical across MMR orders 1-3, smooth/noise input,
both chroma phase methods and invalid-sample inputs, including error flags.

Performance (N150, P7 FEL fixture, 3 x 20 s playback per variant, GPU event medians)
                     0.2.1 engine     0.2.2 engine
Chroma/MMR             8.66 ms          8.08 ms
All reconstruction    18.15 ms         16.26 ms
Kodi processing_ms p50 is unchanged (~8.9 ms): at 24 fps the GPU work overlaps it.

Playback checks (play, pause, resume, seek forward/back, paused seek, Home over video,
return to fullscreen, playback controls, stop; zero errors unless noted)
- N150, 0.2.2 test images: P7 FEL and P8.4 via the native engine pass.
- N150, compatibility renderer forced (DV_PRIVATE_SOURCE=0), P8.4, both colour
  upscaling options: pass. Startup presentation wait 50-70 ms (was 10 s), seeks ~40 ms.
  One frame is dropped by design when the GUI route changes at startup.
- N150, yblod-0.2.2-lg: FEL passes. Add-ons previously recorded as disabled on this
  device were enabled manually (Kodi keeps a recorded add-on state).
- Petunia VM (Tiger Lake), yblod-0.2.2-lg installed over 0.2.2 test builds: the three
  add-ons were enabled automatically on first boot; P8.1 passes.
- Ollie container: kodi-dv:yblod-0.2.2-lg starts; add-ons enabled; the LibreELEC
  settings add-on is kept but its service cannot reach D-Bus in a container.
Seeks near 23-25 s in the FEL fixture return near 3 s and one paused seek was ignored
there; the same happens with the 0.2.1 engine on this image.

Limitations
Checks inspect player/window state, logs and engine byte comparisons, not the
picture on a TV: no visual TV confirmation is part of this report. The compatibility
renderer was exercised by disabling the native engine, not with a stream the native
engine rejects on its own. Fresh-install defaults of the LG edition (Estuary LG skin)
were tested as a script, not with a fresh installation.
