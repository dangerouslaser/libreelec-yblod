Changes since 0.3.4
- Linux 7.3:
  - 9931 lspcon-ls-dv (i915), new: Standard Dolby Vision through a MegaChips MCDP2800 LSPCON
    switched to level-shifter mode (gen9/10).
    - In PCON mode FW 1.77 drops the Dolby VSIF (0.3.4 validation). With
      DVBRIDGE_DV_STANDARD_LAB set, intel_ddi_compute_output_type() returns HDMI for the LSPCON
      port's DP connector. intel_ddi_pre_enable_hdmi() switches the LSPCON to level-shifter mode
      through the standard dual-mode register (I2C 0x40, offset 0x40, over the AUX DDC) with
      TMDS output on; intel_ddi_post_disable_hdmi() switches it back to PCON mode and waits for
      native AUX. The native-HDMI DV path (DV AVI, Dolby VSIF in the VS DIP) then applies.
    - dig_port->hdmi takes the DP connector (DDC = the LSPCON's I2C-over-AUX bridge) and the
      adaptor limit (340 MHz). DV is 4K up to 30 Hz (gen9 HDMI 300 MHz).
    - While in level-shifter mode: DP detect reports HPD only and keeps the EDID; short HPD
      pulses, DP link checks and intel_lspcon_resume() leave the chip alone.
    - Readout: intel_ddi_connector_get_hw_state() accepts an HDMI-mode DDI on that DP
      connector; the InfoFrame hooks use the GPU's DIPs for the HDMI output (output type, or
      lspcon.ls_dv during readout) and the LSPCON's otherwise.
    - QMS is off on LSPCON ports (the VTEM does not fit gen9's 32-byte GMP DIP). Only the
      dolby-vision tunnel format is admitted (no DRM InfoFrame DIP on gen9).
    - DV policy: verified_bridge in place of native_hdmi, and the lab gate admits gen9 for this
      route.
    - i915.dv_lspcon: -1 (default) = DMI allowlist (board vendor Intel Corporation, board
      NUC7i7BNB), 1 = any gen9/10 LSPCON port, 0 = off. At modeset the LSPCON must be MegaChips
      (MCA), branch device ID MC2800, firmware 1.77.
- Docs: HARDWARE.md condition 2, VALIDATION.md (NUC7 level-shifter section).

list the dv_lspcon parameter. kodi.bin, both engines, the runtime defaults, RADV and the remote's
binaries are byte-identical to 0.3.4 (hashes below are 0.3.4's).

Testing
- NUC7i7BNB (MegaChips MCDP2800 HW 2.2 FW 1.77) + LG OLED55C3 (volunteer, 2026-11-09):
  - NUC Display Lab v0.3.1-dvlab (report #15) and v0.4.0-dvlab (report #17), the 0.3.3 Linux 7.3
    with a lab-only i915 patch. The lab switched the LSPCON to level-shifter mode with the same
    dual-mode register and re-probed i915, so the port was HDMI-A-1 on the native-HDMI DV path.
    4K23.976 RGB8 full range:
    - levels 8/8 and 8/8;
    - DV reference without the Dolby VSIF: no DV, raw tunnel;
    - with the VSIF: Dolby Vision and the correct test picture;
    - a frame differing only in its tunnel metadata (L1 max 4095 / avg 3600) shown darker, the
      reference brighter again (the volunteer's visual comparison);
    - a frame with broken metadata CRCs: Dolby Vision too (the C3 does not reject it);
    - back to PCON mode: DP link trained (HBR2 x4), normal picture.
  - NOT tested: the in-modeset switch of linux-9931 (the lab re-probed i915 instead), TV
    off/on and suspend/resume during DV, and Kodi playback on Kaby Lake GT3. This release was
    not played on a TV.
- linux-9931 on Linux 7.3 + the 0.3.4 series: i915 and xe build with -Werror (no warnings);
  the patch applies with patch -p1 to a clean 0.3.4 kernel tree.
- Vulkan and OpenCL engines: byte-identical to 0.3.4, so the 0.3.4 golden checks stand.
- INUC 11i5FL converter route (linux-9930): unchanged; 9931 only acts on VBT LSPCON ports.

Limitations
- The NUC7 route's mode switch inside a modeset has not run on hardware. If it fails, a DV
  title shows no picture on that NUC; i915.dv_lspcon=0 restores the 0.3.4 behaviour (DV
  converted to HDR10).
- One board, one firmware, one TV. Through a soundbar or AV receiver the route is not tested.
- NUC7 DV is 4K up to 30 Hz; Kodi's refresh-rate switching must be on for DV titles.
- HDCP is not supported on the NUC7's DV output (the DP connector's HDCP would use the DP
  method); Kodi does not use HDCP.
- "Convert Dolby Vision to HDR10" is still not offered on the converter's DP connectors.
- The N150's 60p DV (about 40 fps shown) is unchanged.
