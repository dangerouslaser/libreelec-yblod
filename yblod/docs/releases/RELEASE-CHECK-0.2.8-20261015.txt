YBLOD 0.2.8 validation

Build source: 5416c3f3eca25110cd54ad6212a5ba24692c3588 (PR #17 on top of 0.2.7)
The source differs from 0.2.7 only in two add-on pins (service.webostv and
skin.estuary.yblod package.mk). LibreELEC upstream base, FFmpeg, libplacebo, kernel,
Kodi source and patches, native engine, engine defaults and shaders are unchanged.

Changes since 0.2.7
- skin.estuary.yblod 4.1.0+yblod.20 -> 4.1.0+yblod.21 (both editions).
- service.webostv 0.8.8 -> 0.8.9 (LG edition).
Both release zips match the pinned PKG_SHA256. The skin still requires only xbmc.gui;
its LG, Denon and Sonos panels are shown only when those add-ons are present (LG) or
report a connection (Denon, Sonos), so the standard edition shows none of them.

Images
Both: skin.estuary.yblod 4.1.0+yblod.21 in /usr/share/kodi/addons, optional in the
add-on manifest, appliance.xml default skin.estuary.yblod, /usr/lib/yblod/skin-move with
kodi.service.d/30-yblod-skin.conf. LG: service.webostv 0.8.9 and
repository.dangerouslaser 1.0.1, optional.
Comparing every file of the 0.2.7-lg and 0.2.8-lg SYSTEM images: apart from the two
add-ons and the version strings (/etc/issue, os-release, release, kodi/defs.pyc), only
kodi.bin differs. Kodi was recompiled from the same source and patch list; the two
binaries are the same size and differ in one byte, the embedded build date
(20261013 -> 20261015).

Testing
These add-on versions run on Ollie's Kodi container, the Petunia VM and the N150 (from
the dangerouslaser repository, as reported in PR #17); the N150 now runs
service.webostv 0.8.10 and skin 4.1.0+yblod.21 on 0.2.7-lg. The 0.2.8 images themselves
were not installed before publishing; the image checks above are from the built SYSTEM
files. Playback, skin default and skin move were validated on 0.2.6, whose Kodi, engine
and kernel this release keeps.
