YBLOD 0.5.0 validation

Build source: main at 51d4343f8c (tree 7e5613d5), the merge of PR #36, tagged yblod-0.5.0. The
images were built from 11e1d1b570, the head of PR #36, whose tree is identical.
Changes since 0.4.1 (3d947249fb, tree d22aed1c):
- Kodi: the Dolby Vision render and presentation path reworked (yblod-40..49: the engine reads
  the decoded VAAPI surface directly, reset on a new surface pool, repeated pictures held without
  rendering or committing, the GUI buffer handed over only when Kodi drew into it, recovery from
  an engine failure, retried display restore, queued flips behind DV_PRIVATE_NONBLOCK, off by
  default); decoder, EDID, add-on update and diagnostics fixes (yblod-50..58: FEL pairing
  resynchronises, a failed DV decoder falls back, the EDID parser takes HF-EEODB and 25-byte v0
  Dolby blocks, only repository.dangerouslaser may update the optional system add-ons, the fork's
  strings moved to 45000-45999); variable refresh rate (FreeSync) for refresh rate changes
  (kodi-9990, "Variable refresh rate", off by default until it has run on hardware). The series
  is regrouped from 70 patches into 18 (kodi-9900..9908, 9950..9957, 9990; same tree), see
  yblod/docs/KODI-PATCHES.md. DVBridge is only built for x86_64 Generic on GBM, GLES and Vulkan
  (the release image's configuration).
- Kernel: the series regrouped from 30 patches into 13 (same tree), then: QMS only on display
  versions 12 to 29 with a per-CRTC pacer; the Dolby Vision EDID parser takes HF-EEODB EDIDs and
  25-byte v0 blocks; DVBRIDGE_HDR10_DEEP_COLOR and the Lunar Lake HDR10 rule removed;
  i915.enable_dv_lab an ordinary parameter (default on); the amdgpu hdr10 tunnel checks its
  metadata on every change; HDR10+ frame rule only for a new packet; FreeSync over HDMI on i915
  (linux-9933, i915.hdmi_freesync, off by default until it has run on hardware; 1 = while Kodi
  sets VRR_ENABLED).
- Vulkan engine: each frame context's statistics buffer destroyed (a leak per engine teardown);
  cheaper HDR10+ statistics; the HDR10 and HDR10+ pack variants built by dvvk-prepare at boot (94
  pipelines instead of 50); the overlay colour cache and test picture allocated only when used;
  the scanout slots' queued flips and drained writes (the tested C copy of Kodi's logic).
  native-dv.env: DVVK_SURFACE_CHECK=0 (Kodi resets the engine on a new pool), new
  DV_PRIVATE_SKIP_REPEATS=1, DV_PRIVATE_GUI_UNCHANGED_SKIP=1, DV_PRIVATE_NONBLOCK=0,
  DV_PRIVATE_FLIP_TRACE=0.
- FFmpeg: the fork's three patches regrouped into two (same tree). Mesa: the Generic Vulkan
  driver filter dropped (config/graphic already gives amd and intel; only the order changed).
  libplacebo: the upstream recipe restored and the nine fork patches dropped (nothing in the image
  used it; the engine compiles its own subset, yblod-engine/vk/yblod/placebo).
- yblod/tools/link-patches.sh is a gate and yblod/tools/build.sh runs it; the N150 benchmark
  harness (yblod/tools/bench) and its 0.4.1 and 0.5.0 results.

Rebuilds
The first 0.5.0 build (75260dba1d) was checked as above and staged.
- Second build, 5f4eabfa93: FreeSync over HDMI off by default, because it has not run on
  hardware: linux-9933's "static int hdmi_freesync" starts at 0 and its description and header
  say so; KERNEL-PARAMETERS.md and yblod-engine/README.md changed with it (neither is in the
  image). Rebuilt: linux and the three packages built against it (nvidia, ipset,
  wireguard-tools; their files in SYSTEM unchanged). SYSTEM differed from the first build in
  xe.ko, modules.builtin.modinfo and os-release only. The default was checked without booting:
  modules.builtin.modinfo and xe.ko's modinfo read "i915.hdmi_freesync: ... (0 = off [default],
  1 = with VRR_ENABLED, 2 = also without it)"; in the build tree's vmlinux, whose bzImage is
  this KERNEL, hdmi_freesync is a .bss symbol (nm: "b hdmi_freesync"), and in xe.ko it moved
  from .data to .bss. The decompressed kernels of the first two builds have the same size and
  section table; 304 bytes differ, among them the build host and time and the parameter
  description.
- Third build, 11e1d1b570 (this one): "Variable refresh rate" off by default as well.
  kodi-9990's winsystem.vrr default is false and its header says so; with linux-9933 off the
  setting did nothing on Intel, but amdgpu marks an HDMI FreeSync display as vrr_capable by
  itself, so on AMD the untested path would have been used for every refresh rate change.
  Rebuilt: kodi.
