YBLOD 0.5.1 validation

Build source: feature/yblod-0.5.1 at f0f091fae6f876d3c64a3c05b84d9f074186fcbf (tree 76de91ed). The
images were built from it (BUILD_ID f0f091fae6f876d3c64a3c05b84d9f074186fcbf).
The checks below ran on the build of its parent a3ee503d95 (tree f0261879). f0f091fae6 changes
only a comment in native-dv.env (runtime.env: the SDR output has now been seen on a display),
the integration README and the bench README. Its build (run-release.sh 0.5.1, both editions,
again rebuilding only yblod-engine-vk's install and nothing else that differs) was compared with
a3ee503d95's file by file: KERNEL byte-identical; in SYSTEM, both editions, only
usr/lib/kodi/native-dv.env (that comment, two lines) and etc/os-release (BUILD_ID) differ, so the
engine library, dvvk-prepare, kodi.bin and every other file are the ones checked here.
Changes since 0.5.0 (11e1d1b570, tree 7e5613d5), 32 commits:
- SDR output: the Vulkan engine converts Dolby Vision, HDR10, HDR10+ and HLG to an ordinary 8-bit
  picture for a display without Dolby Vision or HDR (DVVK_OUTPUT_SDR, any canvas size). Kodi:
  kodi-9958 (the Dolby Vision bridge at the display mode's size), kodi-9959 (Output mode "Convert
  to SDR" and the Automatic fallback), kodi-9960 (HDR10, HDR10+ and HLG videos through the SDR
  output); kodi-9909 makes Hable Kodi's default tone mapping method. native-dv.env: DV_SDR_OUTPUT=1,
  DV_SDR_WHITE=203, DV_SDR_BLACK=0, DV_SDR_GAMMA=bt1886, DV_SDR_RANGE=auto, DV_SDR_DITHER=1,
  DV_SDR_HDR_SOURCES=1.
- SDR speed and precision (yblod-engine/vk): the 3D LUT over the reconstructed Y'CbCr codes, a
  row's dither ranks in one load, HLG above nominal white and PQ R'G'B' above 1 not clamped, PQ to
  a float's precision in the SDR map.
- Refusal fallback: kodi-9961, a title the Vulkan engine refuses (24 refused pictures over 3 s)
  restarts as its base layer.
- OSD output mode: kodi-9962, the playing title's output in the video OSD (Video settings >
  Output mode), strings 45142-45145; static HDR10 to Dolby Vision for HDR10 sources.
- HDR10+: yblod_hdr10plus.c takes an itu_t_t35_country_code of 0 (stock FFmpeg) as 0xB5.
- MMR: engine.rs runs single-layer MMR pictures (CB1's 4:2:0 piecewise path) under the CB1
  contract; they were refused in 0.5.0.
- Engine ABI: dvvk_create_canvas, dvvk_output_modes and dvvk_hdr10_to_dovi added (optional
  symbols), dvvk_hdr10_static.primaries takes one of its reserved words; DVVK_ABI_VERSION 3.
- Docs, the SDR output plan, and the bench harness on the AMD box with its 0.5.0 results (not in
  the image).

Testing
- Engine, with the release library (ded12053, extracted from SYSTEM; the same file in both
  editions), on Ollie's UHD 770 (Mesa 26.2.6 in yblod-040-engine-dev). The tools are from this
  commit (yblod-engine archived from a3ee503d95, built with the host toolchain), linked against
  the release library:
  - cargo test: 39 of 39 pass (0.5.0's 38 and static_to_dovi_plans).
  - golden.sh check on the 1917 FEL, Gemini Man MEL and 28 Years Later P8.1 clips: identical (102
    hashes), FLIP_Y twins identical (18). The same golden.sha256 as 0.5.0.
  - HDR10 output: the 15 dumps (cb1-hdr10-ref's frames of 1917, 28 Years Later and Gemini Man,
    with and without --cb1, a static overlay) identical to hdr10-base.log and to the 0.5.0 release
    library's, run beside it.
  - sdr-check.sh check, strict, against the committed tools/sdr.sha256: every sample within 1 code
    of the CPU map (78 pictures), FLIP_Y twins identical, hashes identical (78).
  - Byte for byte against CB1's own code: dvvk-mr-compare (cb1-vk-root image) with the release
    library mounted as its engine, every output byte including the embedded metadata packets, 48
    frames per passage, none refused. 0.5.0's nine passages: 432 of 432 identical (1917 P7 FEL
    from the start and 30:40, Gemini Man P7 MEL the same two, 28 Years Later P8.1 the same two,
    12 Angry Men P8.1 letterboxed from 10 min, the DV NASA demo P5, Saving Private Ryan P7 FEL
    from 1:49:40). The MMR pictures 0.5.0 refused: 144 of 144 identical (Basic Instinct P8.1 MMR
    from 30 min, Planes, Trains and Automobiles P8.1 MMR from 20 min, the Profile 8.4 sample from
    the start).
  - ABI: soname libdv_engine_vk.so.1; NEEDED unchanged (libva.so.2, libgcc_s.so.1, libm.so.6,
    libc.so.6, ld-linux-x86-64.so.2); 0.5.0's 25 exported symbols all present, plus
    dvvk_create_canvas, dvvk_hdr10_to_dovi and dvvk_output_modes (28). dv_engine_vk.h:
    DVVK_ABI_VERSION 3 unchanged; the changes are additive (new enum values, new functions, a
    reserved field named; every struct's size and existing offsets unchanged, asserted in the
    header).
  - dvvk-prepare from the image, run in the standard SYSTEM imported as a container (render node,
    empty /storage, nothing else on the GPU): 112 of 112 pipelines (0.5.0's 94 and 18 SDR),
    DVVK_PREPARE_READY, exit 0; 98 s from cold caches, twice (0.5.0: 85 s), 0.46 s with its 20.9
    MB pipeline cache (0.5.0: 17.1 MB). The SDR HLG variants are left to first use by design.
- Static, at this commit: link-patches.sh "patch links OK"; tools/pkgcheck kodi and

Limitations
- Not run for this report: anything on a test box or a display (see Hardware); the engine's 4 CPU
  tests (the C sources they cover, scanout slots, polynomial FEL, order-2 gate and source
  geometry, are unchanged since 0.5.0, where they passed); the SDR real-source tiers (src.sh on
  the HLG, HDR10+ and P8.4 clips) and the HDR10+ country-code byte check, with the release
  library: they ran during development on host-toolchain builds (the HLG tier on this source,
  ~/yblod-050/sdr/out-final, speed/logs/src-final.log; HDR10+ and P8.4 on the fixes branch,
  ~/yblod-050/sdr-sources/res-fixes), not on the image's library; the
  pkgcheck of other packages (their recipes are unchanged since 0.5.0's run). Ollie's engine runs
  prove the library's pixels, not Kodi's use of it: kodi-9958 to 9962 (SDR selection and
  fallback, the refusal restart, the OSD output mode) have no automated check here.
- The CB1 comparison covers the Dolby Vision output only; CB1 has no SDR output, so the SDR
  pictures are checked against the engine's own CPU map and committed hashes.
- All 0.5.0 limitations apply.
