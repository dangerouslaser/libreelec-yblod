Changes since 0.3.3
- Linux 7.3:
  - 9930 dp-pcon-dv (i915), new: Standard Dolby Vision through an onboard DP-to-HDMI protocol
    converter on gen11+.
    - The Dolby VSIF (OUI 00-D0-46, signal 1) goes to the converter as a DP InfoFrame SDP in
      the GMP DIP (00 81 1d 4c, version, length, PB1..PB26; PB27 reserved and checked to be
      0). The DV AVI (CTA VIC, RGB, full range, no colorimetry) goes as an SDP in the AVI DIP.
      The VS DIP is not used: it blanks the verified converter's output.
    - DVBRIDGE_DV_STANDARD_LAB is attached to allowed non-eDP DP connectors.
    - At modeset the route must be a DP branch with an HDMI DFP and an HDMI sink. The link
      policy applies (verified_bridge in place of native_hdmi), and the compute_formats() retry
      without the downstream TMDS limit is skipped for DV.
    - Readout rebuilds the HDMI InfoFrames from the DIPs for the state checker.
    - i915.dv_pcon: -1 (default) = DMI allowlist (board vendor Intel Corporation, board
      CM11EBV58W: INUSUAL INUC 11i5FL), 1 = any gen11+ HDMI-capable non-LSPCON DP port, 0 = off.
  - 9928 big-fella-tunnel-format (i915, amdgpu), from feature/dv-hdr10-output:
    DVBRIDGE_TUNNEL_FORMAT (dolby-vision, the default / hdr10 / lldv) on HDMI connectors. Not
    used by Kodi in this release. The committed copy's stray intel_hdmi.c.orig hunk was dropped.
- dv-engine-vk: big-fella feature/dv-hdr10-tonemap (0.1.0-20) HDR10 output: optional symbols
  dvvk_set_output_mode / dvvk_output_signal, no soname or ABI change. Nothing calls them in
  this release. Source identical to feature/dv-hdr10-output eccc424844 (yblod-engine/vk).
- Not included: Kodi yblod-29 (Output mode HDR10 through the tunnel), only compile-checked.

Images
Standard and LG SYSTEM differ only in the LG add-ons, the add-on manifest and the version strings.
Against 0.3.4-test1 (0.3.3 + linux-9930), SYSTEM differs only in the version strings, xe.ko and
the Vulkan engine; KERNEL differs (linux-9928). kodi.bin, the OpenCL engine, the runtime
defaults, RADV and the remote's binaries are identical to 0.3.3 (hashes below).

Testing
- Converter route, INUSUAL INUC 11i5FL + Sony Bravia 7 (volunteer, 2026-11-08):
  - NUC Display Lab v0.3.0-dvlab (report #13; the same Linux 7.3 with a lab patch): the Dolby
    VSIF SDP in the GMP DIP gives Dolby Vision and the correct test picture at 4K23.976 and
    4K59.94. In the VS DIP the output is black. The TV also showed Dolby Vision for a frame
    with broken tunnel metadata CRCs (it doesn't reject them).
  - Test image 0.3.4-test1 (0.3.3 + linux-9930 only): Dolby Vision playback in Kodi confirmed.
  - The release image was not re-tested on the TV. It adds linux-9928 to that kernel, which only
    changes HDMI connectors' compute and a tunnel check that needs a YCbCr 4:2:2 AVI (the
    converter route sends RGB).
- linux-9928 + linux-9930: i915 and xe build without warnings (Linux 7.3 + the yblod series).
  The release vmlinux has dv_pcon, the CM11EBV58W allowlist and DVBRIDGE_TUNNEL_FORMAT.
- Vulkan engine, the release image's libdv_engine_vk.so.1 on Ollie (UHD 770):
  golden.sh check, 1917 FEL + Gemini Man MEL + 28 Years Later P8.1: identical (90 hashes),
  FLIP_Y twins identical (18). Dolby Vision output is unchanged.
  The HDR10 output was checked by its author: every pixel within one 12-bit code of the CPU
  double-precision Master Reference map; cargo test 34 of 34.
- NUC7i7BNB (MegaChips MCDP2800 FW 1.77) + LG C3 (volunteer, report #8): no route. The firmware
  forwards the HDR10 SDP but drops the Dolby VSIF from the VS and GMP DIPs. LSPCON stays excluded
  (yblod-engine/docs/intel-dv/VALIDATION.md).

Limitations
- Only one converter board is allowlisted and verified, with one TV. Through a soundbar or AV
  receiver the route is not tested.
- The release image itself was not played on a TV (see above).
- "Convert Dolby Vision to HDR10" is not offered on the converter's DP connectors.
- The engine's HDR10 output and linux-9928 are present but unused; they have not run in Kodi.
- The N150's 60p DV (about 40 fps shown) is unchanged.
