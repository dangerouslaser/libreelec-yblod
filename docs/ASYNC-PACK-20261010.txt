Bounded asynchronous packing experiment — tested opt-in
======================================================

Prerequisite: GUI cache results in GUI-CACHE-20261010.txt qualify proceeding.
Neither caching nor asynchronous packing is enabled in release defaults.

Additive ABI4 pack_begin / pack_complete separates queuing from publication.
Only one pack may be pending. Decoded inputs, source planes and GL imports stay
owned until completion/cancellation drains successfully. A nonblocking GUI
error read targets renderer-owned memory. GL release follows all packing and
error reads on the in-order queue. The output becomes valid only after exact
frame ID / PTS validation, release completion and successful error validation.
Failed completion retains ownership; a plain drain discards publication.
The existing synchronous present entry points retain their behavior.

N150 lifecycle test passed using real CL user events (not GL images): poll
not-ready, wrong ID/PTS rejection, bounded submissions, output selection guard,
successful publication, GUI error rejection, cancel/drain discard and failed
event ownership retention. This does not yet validate packing pixels or KMS.

Kodi candidate: DV_PRIVATE_ASYNC_PACK=1, direct scanout only. After successful
display commit, queue packing for the already-prefetched next frame into the
other scanout slot. At consumption, complete and validate before marking the
slot ready. Packet ID/refresh come from that slot's immutable lease, after the
previous commit. The current scanout buffer is never selected for writing.
Cancel/seek/identity miss drains before rejecting the pending lease.

The playback experiment uses clean frames. If GUI appears, cancel/discard
speculative movie-only packing and regenerate with the current overlay; do not
reuse a GUI texture that Kodi may overwrite. After an overlay frame, no pack
is queued ahead. This isolates the scheduling change; overlay packing remains
synchronous and benefits from the separately tested GUI caches.

begin still waits for reconstruction readiness; this wait is explicitly counted
in pack enqueue time, not hidden. Kodi processing_ms includes prefetch submit,
pack enqueue and consume costs. GPU event durations overlap those host costs.
Compare total processing and tails, not just the shortened consume call.

Qualification covers the two 4K24 fixtures below, not all profiles/rates/skins.

Initial deployment completed FEL playback with zero reported drops/skips or
stalls. fel-verify.json is NOT the asynchronous accuracy qualification: its
six diagnostic samples were mostly startup fallback frames. The diagnostic
now requires prepacked=true when the asynchronous flag is enabled, and logs
that fact explicitly. Timing from verification runs is not an A/B benchmark.
Baseline captures fel-off.json and p84-off.json keep both GUI caches enabled
and disable packing-ahead and readback verification.

The revised fel-verify-prepacked.json and p84-verify-prepacked.json each contain
six byte-exact asynchronous frame checks against the existing CPU packing
oracle, explicitly logged as prepacked=true. This checks reconstructed-plane
packing and payload, not end-to-end HDMI capture or a new reconstruction oracle.

Final qualification
-------------------
Verification-OFF transition repeats reached Home and fullscreen, resumed after
seek, and stopped/reopened successfully for both fixtures. Each recorded zero
drops and one transition skip with async ON, and also zero drops and one skip
with async OFF. No continuing skips/stalls or captured ownership/rejection
errors. This is no observed incremental transition regression, not a claim of
perfect switching or a substitute for visual GUI qualification across skins.

OFF rechecks bracket the ON captures and use the exact final binary above
(the first OFF captures preceded the diagnostic-only sampling/log change):
                       Final OFF median/p95    ON median/p95
P7 FEL clean           13.492 / 14.078 ms       10.712 / 10.964 ms
P8.4 clean             11.294 / 12.698 ms        8.862 /  9.086 ms
Same-binary median improvement: 20.6% FEL, 21.5% P8.4. Each has 453 timing
records after warmup. Both OFF rechecks also report no drops/skips/stalls.

Goal audit:
- Unchanged GUI colour and raster caching: implemented behind opt-in flags;
  exact cache tests, live verification, before/after and repeat data recorded
  in GUI-CACHE-20261010.txt. Added memory cost is explicitly documented there.
- Bounded asynchronous packing: one pending pack, two existing scanout buffers;
  identity, ownership, failure, cancel and publish gates exercised by the CL
  lifecycle test and existing 1000-transition scanout slot regression test.
- Playback accuracy/performance: twelve explicitly asynchronous frames passed
  the byte oracle; paired/remeasured timings, GUI changes, seeks and restarts
  completed on N150. Host geometry/order2/polynomial regression tests pass.

Keep the features experimental and OFF in shipped defaults. The measured gain
supports further use, not broad all-profile/4K60 certification. The known single
GUI-transition skip also occurs without async and is not resolved by this work.
The async experiment does not run overlay packing ahead; speculative clean
packing is discarded when controls appear. No output arithmetic was changed.
