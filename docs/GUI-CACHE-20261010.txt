Experimental exact GUI pixel cache — IN PROGRESS
================================================

Goal: cache unchanged GUI processing, compare correctness/performance, then
consider bounded asynchronous packing only after the caching result qualifies.

DV_OVERLAY_PIXEL_CACHE=1 opts into the existing float4 GUI prepass plus a uint32
RGBA key per output pixel. The kernel reads current GUI RGBA, compares it exactly
to the stored key, and skips colour calculation/writing when identical. A change
in any of the 31 float colour coefficients invalidates all pixels and regenerates
the grayscale lookup. Source pixels, sampling and output packing are unchanged.
Failure or overlay disappearance invalidates the cache. No skin hints are used.

Extra buffers at 3840x2160: 132710400 bytes float4 colours + 33177600 bytes RGBA
keys = 165888000 bytes (158.203125 MiB). Existing grayscale table is 1 MiB.
This is experimental and not enabled in shipped native-dv.env.

DV_OVERLAY_CACHE_VERIFY=1 dispatches an independent fresh per-pixel colour
calculation after cache preparation, compares all four float bit patterns and
sets the existing failure flag on any difference. This is deliberately expensive
and disabled during performance measurements. 122 successful P8.4 Home overlay
presentations passed this check on N150. This is not yet comprehensive testing
of forced metadata changes, seeking, subtitle transitions or output geometry.

Initial P8.4 Home before/after (20-second captures, first 24 records excluded):
                         Before       Pixel cache
Kodi processing median   93.021 ms     26.872 ms
Kodi processing p95      93.870 ms     47.738 ms
Overlay packing GPU      62.958 ms      9.146 ms
GUI preparation GPU       fused        3.212 ms
RAM read MiB/s            3674.58       9281.47
RAM write MiB/s           2596.43       4908.30

Processing median improved 71.1%, but p95 still exceeds 41.7 ms. Cached playback
produces more frames per wall-clock interval, so increased system memory traffic
cannot be interpreted as an equal-frame comparison. GPU/host times overlap.
This is a promising candidate, not an optimal/final result or release decision.

Cold-start shader compilation exposed a runner issue: startup fullscreen could
override the Home command. The runner now waits for the video clock to reach
two seconds before setting the target window and records qualified_window.
p84-cache-verify-home.json is UNQUALIFIED (ended fullscreen; only three startup
overlays). p84-cache-verify-home-warm.json and before/after runs ended on Home.
