Settings investigation
PVR fallback framerate was OFF. A temporary 50 Hz fallback test did not supply
the initial rate on this input path, which again configured at 0 fps. The
setting was restored to OFF. A fixed fallback is not appropriate for the
user's mixed-rate playlist and is not part of this change.
The installed ffmpegdirect addon has Probe for FPS enabled by default and no
saved override. Its service being loaded does not establish that it demuxed
this particular playback. No addon configuration was changed.

Change
For realtime streams with no initial FPS, pass the decoder's parsed frame
rate through ProcessInfo and use it before renderer configuration. Accept
positive rates in the existing 5..120 fps range; retain normal duration
normalization and interlaced output-rate handling. Existing stream rates and
non-realtime movie playback are unaffected. Timestamp-based correction remains
available. This does not assume all channels are 50 Hz.

or the exact first visible frame. Startup can still contain separate initial
HDR and refresh commits; this patch does not merge all HDMI transitions.

Limitations
Streams without reliable decoder timing still use Kodi's existing frame-rate
detection. No new bounded buffering policy is implemented. Mixed/VFR material
and interlaced live sources require further coverage. This is a targeted fix
for the demonstrated missing-demux-rate/available-decoder-rate case, not proof
of seamless startup for every IPTV channel.
